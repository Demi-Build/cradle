Library reuse

Reuse has to feel like the asset was always yours. That means the unit is a bundle, the import adapts to the receiving pack's palette before you confirm, and the provenance is stamped rather than lost — a borrowed character with someone else's colours is not reuse, it is a paste.

Search covers name, tags, type, resolution and source project. The card previews the bundle's parts, not a single thumbnail, because the parts are what make it reusable.
Runs the recolour machinery from P3 against the receiving pack's style palette: role-name match first, luminance match second, and an explicit list of frames it could not resolve. Every frame is previewed adapted, not just the anchor.
Mints a fresh id, writes the adapted frames as this pack's own artifacts, and stamps library_ref plus the original project. The History tab shows the import as the first row of lineage.

failure · palette cannot resolve

A source with nine roles into a pack with five: “4 roles have no match here. Import maps them to the nearest luminance and flags 12 frames off-palette.” The preview shows those frames first, and importing anyway is a legitimate choice.

empty state

An empty library is the common first state: “Nothing published yet. Publish a character or tileset from any project and it appears here.” One button, pointing back at the current pack — never a marketplace teaser.

scope

Local machine only; no sharing, no accounts. Engine copies and project templates are explicitly not library items — the library holds content, not machinery.
