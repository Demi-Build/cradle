# Cradle

A read-only desktop inspector for worlds generated by [canon](../canon) — "RPG Maker for AI-generated worlds."

Cradle is the companion GUI to canon, a Python library that provides coherence tooling for AI-generated game content (World Bible, 3-stage validation pipeline, retry-with-feedback). Cradle renders canon's output so you can walk the generated world without running the game.

The reference implementation of canon lives inside **MazeWorld**, an AI-orchestrated 2D RPG where NPCs, items, quests, portraits, music, and SFX are all generated from a single `STORY_SEED` via a skeleton-driven pattern. Cradle's primary test target is a MazeWorld-generated world.

## Status: v0.1 (read-only shell)

v0.1 is a static inspector. Editing lands in v0.2, live dialogue in v0.3, simulation adapters in v0.4+.

**In scope for v0.1:**
- Load a World Bible and its generated assets from disk
- Browse all generated entities by type (NPCs, items, monsters, quests, rooms, events, classes)
- Inspect raw JSON for any entity
- Three-pane layout (top bar / left nav / detail / validation status)

**Not yet:**
- Entity detail tabs (overview / stats / generation trail / assets)
- Dialogue graph + card views
- Table/sort/filter views for entity lists
- Asset rendering (portraits, sprites, audio)
- World picker dialog — paths are typed into the top bar for now
- Any form of editing or regeneration

## Stack

- **Tauri 2** (Rust backend, native webview) — cross-platform; macOS and Windows bundles via `npm run tauri build`
- **React 19 + TypeScript + Vite** frontend
- **zustand** for selection state
- No runtime dependency on canon — cradle reads canon's already-validated JSON output. Schema typing lands in v0.2 once canon stabilizes.

## Data layer

Cradle talks to a `DataSource` trait in `src-tauri/src/data.rs`. v0.1 ships one impl, `LocalFsDataSource`, which reads from a local `world_output/` directory. A future `RemoteDataSource` (for a collaborative/server-hosted mode) can slot in behind the same trait without frontend changes — all IPC goes through typed wrappers in `src/lib/invoke.ts`.

Expected world layout (matches MazeWorld's output):

```
<world>/
  data/
    world_bible.json
    manifest.json
    narrative.json
    generation_stats.json
    npcs/npcs.json
    items/items.json
    monsters/monsters.json
    quests/quests.json
    events/events.json
    classes/classes.json
    rooms/<room_id>/maze.json
    portraits/...
    music/*.mp3
    sfx/*.mp3
```

A reference world ships in `bibles/mazeworld_5_room_demo/`.

## Development

### Prerequisites

- Node 20+
- Rust toolchain (install via [rustup](https://rustup.rs))
- Platform build deps for Tauri — see the [Tauri prerequisites](https://tauri.app/start/prerequisites/) page for your OS

### Setup

```
npm install
```

### Run

```
npm run tauri dev
```

In the top bar, paste the absolute path to a world directory (e.g. the bundled `bibles/mazeworld_5_room_demo`) and hit Load. The left nav populates with entity types; click one to expand, click an entity to view its JSON.

### Build

```
npm run tauri build
```

Produces a platform-native bundle in `src-tauri/target/release/bundle/` — `.dmg`/`.app` on macOS, `.msi`/`.exe` on Windows.

### Type-check / Rust-check

```
npx tsc --noEmit
cd src-tauri && cargo check
```

```
    App.tsx
  src-tauri/            Rust backend
    src/
      data.rs           DataSource trait + LocalFsDataSource
      lib.rs            Tauri commands
    tauri.conf.json
    Cargo.toml

```
