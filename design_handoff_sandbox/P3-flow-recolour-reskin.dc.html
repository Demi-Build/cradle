cradledoes the work
Role selection reads the style palette, so “the cloak” is a query rather than a lasso. The selection is stored with the operation, which is what makes it repeatable across frames.
The remap is deterministic and reversible: a colour map plus a region mask, applied per frame. Nothing is resampled, so pixel edges are untouched.
Applies the map to every frame of every state and the expression sheet, and lists any frame containing unmapped colours from the region.
A skin writes one journaled version holding the colour map, not a copy of the pixels — the content-addressed store keeps one set of frames. A new character mints a fresh id with parents pointing at the base.
Because a skin is a map, later edits to the base's pixels flow into it. That is the reason to prefer skin over new character — and the reason a diverging design should not be a skin.

answered here

Recolour lives in the pixel editor only. An entity quick-action would need its own selection UI to be useful, and two selection models is how the tool ends up inconsistent.

empty state

Tool armed, nothing selected: “Select pixels, or click a palette role to select every pixel using it.” The remap panel is present and disabled, not absent.

edge case

Recolouring a skin: allowed, and it stacks as a second map. Three deep, the UI stops offering it and says to save a new character instead.
